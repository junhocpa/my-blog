- 스크래치패드(저장소 밖)에 최소 DOM 스텁 하네스를 만들어 **editor.js 원본을 그대로 로드**해 실행. **27건 전부 통과.**

## 3. 발견한 문제와 수정 내역

### 문제 1 — 창 밖에서 마우스 버튼을 떼면 드래그 상태가 남음 (수정함)

- **증상**: 격자에서 `pointerdown` 후 마우스를 브라우저 창 밖으로 끌고 나가 버튼을 떼면, 문서 레벨 `pointerup`이 전달되지 않아 `state.drawing`이 `true`로 남는다. 이후 창으로 돌아와 버튼을 누르지 않고 격자 위를 지나가기만 해도 셀이 칠해진다.
- **수정** (`editor.js`, `pointermove` 핸들러): 마우스 포인터인데 `e.buttons === 0`이면 드래그를 종료하고 칠하지 않도록 가드 추가.

```js
if (e.pointerType === "mouse" && e.buttons === 0) {
  state.drawing = false;
  return;
}
```

- **재검증**: Node 회귀 테스트 2건 추가(buttons=0 이동은 칠하지 않고 종료 / 종료 후 move만으로는 칠하지 않음) + 브라우저에서 동일 시나리오 합성 이벤트로 확인. 모두 통과. 터치/펜은 `pointercancel`·`pointerup`으로 기존 로직이 처리하므로 마우스로 한정했다.

## 4. 남은 이슈·개선 제안 (수정하지 않음)

1. **빠른 드래그 시 셀 건너뜀**: `pointermove` 발생 지점만 칠하므로 아주 빠르게 드래그하면 중간 셀이 비어 있을 수 있다(자동화 드래그에서 81→85→88처럼 관찰됨). 실제 포인터는 move 이벤트가 조밀해 체감 문제는 작고, 스펙도 선형 보간(선 긋기 도구)을 요구하지 않아 스펙 위반은 아니다. 개선하려면 이전 좌표와 현재 좌표 사이를 보간해 칠하면 된다.
2. **키보드 접근성**: 격자가 `role="img"`인 div 셀이라 키보드만으로는 그릴 수 없다. 스펙이 요구하지 않는 범위(비목표에 준함)라 이슈로만 기록한다.
3. **스펙 참고 사항**: spec.md는 `aria-label`에 색 이름만 예시("빨강")로 들었는데 구현은 "빨강 (#e53935)" 형식이다. 정보가 더 많은 방향이므로 문제 없음.

## 5. 검증 환경 비고

- 브라우저 검증은 임시 정적 서버(127.0.0.1:8899, Node http)로 수행했고 검증 후 서버를 종료·포트 해제를 확인했다. (기존 8642 서버는 사용하지 않음)
- 초기 화면은 스크린샷으로 확인했으나, 이후 브라우저 패널 screenshot 액션이 타임아웃되어(지침에 예고된 제약) 나머지 시각 검증은 DOM·computed style 검사와 합성 PointerEvent로 대체했다. 기능 판정에는 영향 없다.
- 검증 도중 브라우저 패널 폭이 바뀌며 자동화 클릭 좌표가 일부 어긋나 의도치 않은 셀이 칠해졌으나, 이는 검증 환경 문제이며 앱 동작은 모두 정상이었다(오히려 여러 색 클릭 채색이 추가로 확인됨).

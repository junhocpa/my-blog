# 픽셀 아트 에디터 웹앱 — 구현 스펙 (spec.md)

블로그 저장소 내 `apps/pixel-art/` 폴더에 자체 완결형으로 들어가는 픽셀 아트 에디터 웹앱의 구현 계획서.
순수 HTML/CSS/JavaScript만 사용하며, 외부 라이브러리·프레임워크·번들러를 쓰지 않는다.
`index.html`을 `file://`로 직접 열어도 동작해야 하므로 **ES 모듈을 사용하지 않고 `<script defer>` 일반 스크립트**로 로드한다.

---

## 1. 앱 개요 및 핵심 사용 흐름

### 1.1 개요
- **16×16 격자**에 도트(픽셀)를 찍어 그림을 그리는 간단한 픽셀 아트 에디터.
- 완성한 그림은 **PNG 파일로 다운로드**할 수 있다 (16×16 원본은 너무 작으므로 **20배 확대한 320×320 PNG**로 저장).

### 1.2 핵심 사용 흐름
```
① 팔레트에서 색 선택 (또는 커스텀 색상 피커로 원하는 색 지정)
        ↓
② 격자를 클릭/드래그(터치: 탭/스와이프)해서 도트 찍기
        ↓
③ 실수한 부분은 지우개로 지우기 (또는 전체 지우기로 리셋)
        ↓
④ [PNG 저장] 버튼 → pixel-art.png (320×320) 다운로드
```

## 2. 기능 목록

| # | 기능 | 설명 |
|---|------|------|
| F1 | 16×16 격자 캔버스 | 256칸 격자 렌더링. 빈 칸(투명)은 체커보드 무늬로 표시 |
| F2 | 클릭으로 도트 찍기 | 칸 클릭 시 현재 선택 색으로 채움 |
| F3 | 드래그 페인팅 | 버튼을 누른 채 드래그하면 지나가는 칸이 연속으로 칠해짐 |

- 참고: 되돌리기(Undo), 저장/불러오기 등은 비목표(6장 참조).

## 4. 핵심 로직 설계

### 4.1 격자 상태 표현
- `grid`: **길이 256(16×16)의 1차원 배열**. 각 원소는 색상 문자열(`"#ff0000"` 등) 또는 **`null`(투명/빈 칸)**.
- 인덱스 ↔ 좌표 변환: `index = row * 16 + col`.
- 도구 상태:

```
state = {
  grid:  (string|null)[256],  // 픽셀 색상, null = 투명
  color: string,              // 현재 선택 색 (예: "#1e88e5")
  tool:  "pen" | "eraser",    // 현재 도구
  drawing: boolean            // 드래그 페인팅 중 여부
}
```

### 4.2 격자 렌더링 방식 — DOM 격자 채택
- **편집 화면은 `<canvas>`가 아닌 DOM 격자**(256개의 `<div class="cell">`를 CSS Grid로 배치)로 구현한다.
  - 이유: 칸 단위 이벤트 처리·터치 좌표 계산이 단순하고, 체커보드/호버 표시를 CSS만으로 처리 가능. 256칸 규모에서는 성능 문제 없음.
  - `<canvas>`는 **PNG 내보내기 시에만** 오프스크린으로 사용(4.4 참조).
- 각 칸은 `data-index` 속성으로 자신의 인덱스를 가진다. 칠해진 칸은 `style.backgroundColor`를 직접 설정, 빈 칸은 배경색 제거(체커보드는 격자 컨테이너 배경으로 표현).

### 4.3 그리기 이벤트 처리 — Pointer Events로 통합
마우스·터치·펜을 **Pointer Events 하나로 통합** 처리한다 (`mousedown`/`touchstart` 이중 구현 불필요).

```
paintAt(index):
    value = (state.tool == "eraser") ? null : state.color
    if grid[index] != value:
        grid[index] = value
        해당 셀 DOM 업데이트 (전체 재렌더 불필요)

격자 컨테이너에 이벤트 위임:
  pointerdown → state.drawing = true
                setPointerCapture 대신 문서 레벨 pointerup으로 종료 감지
                이벤트 좌표의 셀을 찾아 paintAt()
  pointermove → if state.drawing:
                    // 터치 드래그에서는 event.target이 시작 셀에 고정되므로
                    document.elementFromPoint(e.clientX, e.clientY)로
                    실제 아래에 있는 셀을 찾아 paintAt()
  pointerup / pointercancel (document 레벨) → state.drawing = false
```

- 격자에 CSS `touch-action: none` 적용 — 드래그 페인팅 중 화면 스크롤 방지 (필수).
- 드래그 중 브라우저 기본 드래그/텍스트 선택 방지: `user-select: none`, `dragstart` 방지.

### 4.4 PNG 생성·다운로드
화면 DOM과 무관하게, 내보내기 시점에 오프스크린 `<canvas>`에 상태를 그려서 저장한다.

```
EXPORT_SCALE = 20          // 16 × 20 = 320
function exportPNG():
    canvas = document.createElement("canvas")
    canvas.width = canvas.height = 16 * EXPORT_SCALE   // 320×320
    ctx = canvas.getContext("2d")
    // 배경은 채우지 않음 → 빈 칸(null)은 투명 픽셀로 남음
    for i in 0..255:
        if grid[i] != null:
            ctx.fillStyle = grid[i]
            ctx.fillRect((i % 16) * SCALE, floor(i / 16) * SCALE, SCALE, SCALE)
    a = document.createElement("a")
    a.href = canvas.toDataURL("image/png")
    a.download = "pixel-art.png"
    a.click()
```

- `toBlob` + `URL.createObjectURL`도 가능하나, 320×320 수준에서는 `toDataURL`로 충분하고 코드가 단순하다.
- `fillRect`는 정수 좌표만 사용하므로 안티앨리어싱 없이 선명한 픽셀이 보장된다.

### 4.5 팔레트·도구 처리
- 기본 팔레트 16색(예시): 검정, 흰색, 회색, 빨강, 주황, 노랑, 연두, 초록, 청록, 하늘, 파랑, 남색, 보라, 분홍, 갈색, 살구. 정확한 HEX 값은 구현 시 명도 대비를 보며 확정.
- 팔레트 스와치 클릭 → `state.color` 갱신 + `state.tool = "pen"`으로 자동 전환(지우개 상태에서 색을 고르면 바로 그릴 수 있게).
- `<input type="color">` `input` 이벤트 → 동일하게 색 갱신 + 펜 전환.
- 지우개 버튼 → `state.tool = "eraser"`. 선택된 도구/색상은 `aria-pressed` + CSS 강조로 표시.

## 5. UI/UX 설계

### 5.1 레이아웃
```
┌──────────────────────────────┐
│  픽셀 아트 에디터              │  ← 헤더 (제목)
│  ┌────────────────────────┐  │
│  │      16×16 격자         │  │  ← 캔버스 영역 (정사각형,
│  │   (체커보드 배경 위에)    │  │     폭 = min(90vw, 480px),
│  │                        │  │     중앙 정렬)
│  └────────────────────────┘  │
│  현재색■  [🎨피커] [지우개]     │  ← 도구 줄
│  ■■■■■■■■                    │  ← 팔레트 (16색, 2행 그리드)
│  ■■■■■■■■                    │
│  [전체 지우기]  [PNG 저장]     │  ← 액션 버튼 줄
└──────────────────────────────┘
```
- 단일 컬럼, 콘텐츠 최대 너비 약 520px, 중앙 정렬. 격자가 주인공이므로 화면 상단에 배치.
- 격자: CSS Grid `repeat(16, 1fr)` + `aspect-ratio: 1`. 셀 사이 1px 안내선(컨테이너 `gap` 또는 셀 테두리 — 가는 회색).
- 빈 칸 표현: 격자 컨테이너에 CSS로 만든 체커보드 배경(연회색 2톤) — "투명"임을 직관적으로 전달.

### 5.2 디자인 토큰·색상
- 색상·간격은 전부 CSS 커스텀 프로퍼티(`:root` 변수)로 정의, 하드코딩 금지.
- 앱 배경은 밝은 중성색, UI는 미니멀하게 — 사용자가 고르는 색이 돋보이도록 크롬(도구 UI)은 무채색 위주.
- 다크 모드: `prefers-color-scheme: dark`에서 배경·테두리 변수만 어두운 톤으로 전환(자동 대응만, 수동 토글은 비목표). 체커보드도 어두운 2톤으로 교체.

### 5.3 타이포그래피
- 시스템 폰트 스택(블로그와 동일 계열): `"Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`.
- UI 텍스트는 한국어("지우개", "전체 지우기", "PNG 저장" 등).

### 5.4 모바일 대응
- 모바일 우선 작성, `min-width` 미디어 쿼리로 데스크톱 보정.
- 375px 폭에서 가로 스크롤 없이 격자·팔레트·버튼이 모두 보여야 한다. 격자 폭 `min(90vw, 480px)` 수준이면 375px에서 셀 하나가 약 21px — 손가락 드래그로 칠하기에 충분(개별 셀 탭 정밀도는 드래그 페인팅으로 보완).
- 팔레트 스와치·도구·액션 버튼은 터치 대상 최소 44×44px 확보.
- 격자에 `touch-action: none` — 그리는 동안 페이지 스크롤·당겨서 새로고침 방지.

### 5.5 접근성
- 팔레트 스와치는 `<button>`으로 만들고 `aria-label`에 색 이름(예: "빨강") 지정. 선택 상태는 `aria-pressed="true"`.
- 지우개·전체 지우기·PNG 저장 버튼은 텍스트 라벨 포함(아이콘 단독 금지).
- 선택 색/도구의 시각적 강조는 색상만이 아니라 테두리 두께·체크 표시 등 형태로도 구분(색약 대응).
- UI 텍스트와 배경의 명도 대비 WCAG AA 준수.
- 전체 지우기는 실수 방지를 위해 `confirm()` 확인 후 실행.

## 6. 비목표 (구현 범위 밖)

- **되돌리기/다시하기(Undo/Redo)**.
- **레이어, 애니메이션(GIF), 프레임** 기능.
- **파일 불러오기**(PNG import) 및 **작업 자동 저장**(localStorage 보존) — 새로고침 시 그림은 초기화.
- **격자 크기 옵션**(32×32 등) — 16×16 고정. 단, 코드에서는 `GRID_SIZE = 16` 상수로 두어 확장 여지만 남긴다.
- **채우기(페인트 통), 스포이드, 선/사각형 도구** 등 고급 도구.
- **공유·서버 연동** 일체.
- **블로그 빌드 파이프라인 연동**(글 목록에 링크 추가 등) — 별도 작업으로 분리.
- 외부 라이브러리·CDN 사용 (Canvas API + Pointer Events로 충분).

## 7. 구현 순서 제안 (Build 단계 참고용)

1. `index.html` 뼈대 + `style.css` 디자인 토큰/레이아웃 (정적 격자·팔레트가 보이는 상태).
2. `editor.js`: 상태 초기화 + 격자 DOM 생성 + 팔레트/피커 색 선택.
3. 클릭·드래그 페인팅 (Pointer Events + `elementFromPoint`).
4. 지우개 + 전체 지우기.
5. PNG 내보내기 (오프스크린 canvas → 320×320 다운로드).
6. 모바일 반응형·터치 마무리 + 접근성 점검(aria, 대비, 44px 터치 대상).

### 검증 체크리스트
- `file://`로 `index.html` 직접 열어 전 기능 동작 (모듈 오류 없음).
- 드래그로 여러 칸이 연속으로 칠해지는지 (마우스·터치 모두).
- 터치 드래그 중 페이지가 스크롤되지 않는지 (`touch-action: none`).
- 다운로드된 PNG가 320×320이고, 빈 칸이 투명으로 저장되는지 (이미지 뷰어에서 확인).
- 커스텀 피커로 고른 색이 즉시 현재 색이 되고 그려지는지.
- 375px 폭에서 가로 스크롤 없이 전체 UI가 보이는지.

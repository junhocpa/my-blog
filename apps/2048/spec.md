# 2048 게임 웹앱 — 구현 스펙 (spec.md)

블로그 저장소 내 `apps/2048/` 폴더에 자체 완결형으로 들어가는 2048 퍼즐 게임 웹앱의 구현 계획서.
순수 HTML/CSS/JavaScript만 사용하며, 외부 라이브러리·프레임워크·번들러를 쓰지 않는다.

---

## 1. 게임 개요 및 규칙

### 1.1 개요
- 4×4 격자 위에서 숫자 타일을 상·하·좌·우로 밀어, 같은 숫자끼리 합쳐 더 큰 숫자를 만드는 퍼즐 게임.
- 목표: **2048 타일**을 만들면 승리. 이후에도 계속 플레이 가능(무한 모드).

### 1.2 타일 이동 규칙
- 방향 입력 시 **모든 타일이 해당 방향으로 끝까지 미끄러진다** (빈 칸을 건너뛰어 벽 또는 다른 타일에 닿을 때까지).
- 이동 후 보드에 변화가 없으면(어떤 타일도 움직이거나 병합되지 않으면) **무효한 수**로 간주하고 새 타일을 생성하지 않는다.

### 1.3 병합 규칙
- 같은 숫자 타일 두 개가 이동 방향으로 충돌하면 하나로 합쳐지고, 값은 두 배가 된다.
- **한 번의 이동에서 각 타일은 최대 1회만 병합된다.**
  - 예: `[2, 2, 2, 2]`를 왼쪽으로 밀면 `[4, 4, 0, 0]` (❌ `[8, 0, 0, 0]` 아님).
  - 예: `[4, 2, 2, 0]`을 왼쪽으로 밀면 `[4, 4, 0, 0]` (❌ `[8, ...]` 아님 — 병합 결과 4는 기존 4와 다시 합쳐지지 않음).
- 병합은 이동 방향 기준 **먼 쪽(벽 쪽) 타일부터 우선** 처리한다.
  - 예: `[2, 2, 2, 0]`을 왼쪽으로 밀면 `[4, 2, 0, 0]` (앞쪽 두 개가 먼저 병합).

### 1.4 새 타일 생성
- 게임 시작 시 무작위 빈 칸 2곳에 타일 생성.
- 유효한 이동 직후 무작위 빈 칸 1곳에 타일 생성.
- 생성 값: **90% 확률로 2, 10% 확률로 4** (원작 규칙).

### 1.5 점수 규칙
- 병합이 일어날 때마다 **병합 결과값만큼 점수 가산** (2+2=4 병합 → +4점).
- 이동만으로는 점수가 오르지 않는다.

### 1.6 승리·패배 조건
- **승리**: 2048 타일이 처음 만들어진 순간 승리 오버레이 표시. "계속하기" 선택 시 같은 보드로 계속 플레이(오버레이는 게임당 1회만 표시).
- **패배(게임 오버)**: 빈 칸이 없고, 인접(상하좌우)한 같은 숫자 쌍도 없어 네 방향 모두 유효한 이동이 불가능할 때. 게임 오버 오버레이 표시.

```
└── game.js                # 게임 로직 + DOM 렌더링 + 입력 처리 (단일 파일, ES 모듈)
```

- `index.html`에서 `<script type="module" src="game.js">`로 로드.
- 서버 없이 `index.html`을 직접 열어도 동작해야 한다(모듈 로딩이 `file://`에서 막히는 브라우저를 고려해, 단일 JS 파일이므로 필요 시 `defer` 일반 스크립트로 대체 가능 — 구현 시 `file://` 동작을 확인하고 결정).
- 블로그의 다른 파일(`posts/`, `src/`, `build.js` 등)은 일절 건드리지 않는다.

## 4. 핵심 로직 설계

### 4.1 보드 상태 표현
- `board`: 길이 16의 1차원 배열 또는 4×4 2차원 배열(`number[][]`). **0 = 빈 칸**, 그 외 = 타일 값(2, 4, 8, …).
- 전체 게임 상태 객체:

```
state = {
  board:    number[4][4],  // 타일 값
  score:    number,        // 현재 점수
  best:     number,        // 최고 점수 (localStorage 동기화)
  won:      boolean,       // 2048 달성 여부 (승리 오버레이 1회 제어)
  over:     boolean,       // 게임 오버 여부
  keepPlaying: boolean     // 승리 후 계속하기 선택 여부
}
```

### 4.2 이동/병합 알고리즘 (핵심)
모든 방향을 "한 행을 왼쪽으로 민다"라는 단일 연산으로 환원한다.

```
function slideRowLeft(row):        # row: 길이 4 배열
    arr = row에서 0 제거            # [2,0,2,4] → [2,2,4]
    result = [], gained = 0
    i = 0
    while i < arr.length:
        if i+1 < arr.length and arr[i] == arr[i+1]:
            merged = arr[i] * 2
            result.push(merged); gained += merged
            i += 2                  # 병합된 두 타일 소비 → 1이동 1병합 보장
        else:
            result.push(arr[i]); i += 1
    result를 0으로 채워 길이 4로 패딩
    return { row: result, gained, moved: (result != row) }

function move(direction):
    1) 방향에 따라 보드를 변환:
       - LEFT : 그대로
       - RIGHT: 각 행 reverse → slideRowLeft → 다시 reverse
       - UP   : transpose → slideRowLeft → transpose
       - DOWN : transpose + reverse → slideRowLeft → 역변환
    2) 4개 행 각각 slideRowLeft 적용, moved/gained 집계
    3) if 아무 행도 moved 아님: return (무효한 수)
    4) score += gained 합계, best 갱신 및 localStorage 저장
    5) spawnRandomTile()
    6) 2048 최초 달성 시 won=true → 승리 오버레이
    7) checkGameOver() → over=true 시 게임 오버 오버레이
    8) render()
```

### 4.3 랜덤 타일 생성
```
function spawnRandomTile():
    empties = board에서 값이 0인 좌표 목록
    if empties 비어있음: return
    cell = empties에서 무작위 선택 (Math.random)
    board[cell] = Math.random() < 0.9 ? 2 : 4
```

### 4.4 게임 오버 판정
```
function canMove():
    if 빈 칸 존재: return true
    for 각 칸 (r, c):
        if 오른쪽 이웃 또는 아래 이웃과 값이 같으면: return true
    return false
```

### 4.5 입력 처리
- **키보드**: `keydown`에서 `ArrowLeft/Right/Up/Down` 매핑, `event.preventDefault()`로 스크롤 방지. 오버레이 표시 중에는 무시.
- **터치**: 보드 요소에 `touchstart`(시작 좌표 기록) / `touchend`(끝 좌표와 비교).
  - `|dx| > |dy|`이면 좌/우, 아니면 상/하.
  - 최소 스와이프 거리 임계값(약 30px) 미만이면 무시(탭과 구분).
  - 보드 위 스와이프 시 화면 스크롤 방지: 보드에 `touch-action: none` CSS 적용.

### 4.6 렌더링 전략
- **상태 → DOM 전체 재그리기** 방식(단순성 우선): 매 이동 후 보드 컨테이너의 타일 요소를 상태 기반으로 다시 생성.
- 타일 값별 색상은 `data-value` 속성 + CSS 셀렉터(`.tile[data-value="2"]` 등)로 매핑. 4096 이상은 공통 스타일(`data-value` 상한 초과용 기본색).
- 새 타일에 `tile--new`, 병합 타일에 `tile--merged` 클래스를 붙여 CSS 애니메이션 트리거.
- 슬라이드 이동 애니메이션(타일이 미끄러지는 연출)은 **비목표** — 등장/병합 애니메이션만 제공.

## 5. UI/UX 설계

### 5.1 레이아웃
```
┌────────────────────────────┐
│  2048        [SCORE][BEST] │  ← 헤더: 제목 + 점수판
│  같은 숫자를 합쳐 2048을!    [새 게임] │  ← 안내문 + 새 게임 버튼
│  ┌──┬──┬──┬──┐            │
│  │  │ 2│  │ 4│            │
│  ├──┼──┼──┼──┤            │  ← 4×4 보드 (정사각형, 화면 폭 기준
│  │  │  │ 8│  │            │     max 480px, 중앙 정렬)
│  ├──┼──┼──┼──┤            │
│  │ 2│  │  │  │            │
│  └──┴──┴──┴──┘            │
│  조작법 안내 (방향키/스와이프) │  ← 푸터
└────────────────────────────┘
```
- 페이지 전체는 세로 중앙 정렬에 가까운 단일 컬럼. 콘텐츠 최대 너비 약 480px.
- 보드: CSS Grid(`grid-template: repeat(4, 1fr) / repeat(4, 1fr)`), `aspect-ratio: 1`로 정사각형 유지.
- 오버레이: 보드 위에 반투명 레이어(`position: absolute`)로 승리/게임오버 메시지와 버튼 표시.

### 5.2 색상 방향
- 디자인 토큰은 전부 CSS 커스텀 프로퍼티(`:root` 변수)로 정의 — 하드코딩 금지.
- 원작 2048의 웜톤 계열을 참고하되 독자적 팔레트 사용:
  - 배경/보드: 밝은 베이지~그레이 계열, 빈 칸은 보드보다 약간 어두운 톤.
  - 타일: 2·4는 밝은 색+어두운 글자, 8~64는 주황~빨강 계열+흰 글자, 128 이상은 노랑·금색 계열+흰 글자.
  - 숫자가 커질수록 글자 크기 축소(3~4자리 대응): 예 `1024` 이상은 폰트 크기 한 단계 줄임.
- 명도 대비 WCAG AA 준수(타일 배경 대 숫자 색).
- 다크 모드: `prefers-color-scheme: dark`에서 배경·보드 변수만 어두운 톤으로 교체(선택 구현, F10).

### 5.3 타이포그래피
- 시스템 폰트 스택(블로그와 동일 계열): `"Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` + 숫자는 굵게(700).
- UI 텍스트는 한국어(제목 "2048", 버튼 "새 게임", "다시 시작", "계속하기" 등).

### 5.4 모바일 대응
- 모바일 우선 작성, `min-width` 미디어 쿼리로 데스크톱 보정.
- 375px 폭에서 가로 스크롤 없이 보드 전체가 화면에 들어와야 한다(보드 폭 = `min(90vw, 480px)` 수준).
- 터치 대상(새 게임 버튼, 오버레이 버튼) 최소 44×44px.
- 보드에 `touch-action: none`, `user-select: none` 적용(스와이프 중 스크롤·텍스트 선택 방지).

### 5.5 접근성
- 새 게임 버튼 등 컨트롤에 명확한 텍스트 라벨(아이콘 단독 버튼 없음).
- 점수 변경 영역에 `aria-live="polite"` 적용해 스크린리더에 점수 갱신 알림.
- 게임 보드는 시각 중심 콘텐츠이므로 상태 요약(예: "점수 120")을 텍스트로 항상 노출.

## 7. 구현 순서 제안 (Build 단계 참고용)

1. `index.html` 뼈대 + `style.css` 디자인 토큰/레이아웃 (정적 보드가 보이는 상태).
2. `game.js`: 상태 초기화 + 렌더링 (하드코딩 보드가 화면에 표시).
3. `slideRowLeft` + 방향 변환 + `move()` (키보드 조작으로 플레이 가능).
4. 점수/최고 점수 + localStorage.
5. 승리/게임 오버 판정 + 오버레이 + 새 게임 버튼.
6. 터치 스와이프 + 모바일 반응형 마무리.
7. 애니메이션(pop-in/pulse) + 접근성 점검(aria-live, 대비, 44px 터치 대상).

### 검증 체크리스트
- `[2,2,2,2]` → 왼쪽 → `[4,4,0,0]` (이중 병합 방지 확인).
- 무효한 수(변화 없는 방향)에서 새 타일이 생성되지 않는지.
- 375px 폭에서 가로 스크롤 없음, 스와이프 4방향 정상 동작.
- 새로고침 후 최고 점수 유지, 게임 오버 판정(꽉 찬 보드 + 인접 동값 없음) 정확성.

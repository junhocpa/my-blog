# 여의도 전세 매물 수집기

> ## ⚠️ 현재 실제 수집은 되지 않습니다 (2026-08-08 중단)
>
> 네이버 모바일 API가 어떤 요청 형태로도 HTTP 200 + 본문 `null` 만 돌려줍니다.
> URL 형태 6가지, 헤더 추가, 쿠키 첨부, 브라우저 직접 열기까지 모두 같은 결과였습니다.
> 차단(403/429)도 아니고 쿠키 문제도 아닙니다.
>
> **무엇을 시험했고 무엇이 남았는지는 [`STATUS.md`](./STATUS.md) 에 정리해 두었습니다.**
> 다시 시작하실 때 그 문서부터 읽으세요. 아래의 실행 절차는 그 문제가 해결된 뒤에 유효합니다.
>
> 웹앱 화면·필터·정렬·배지는 정상 동작하며, 공개 사이트에서는 예시 데이터로 확인할 수 있습니다.

여의도 및 인근 지역의 **전세 아파트·주거용 오피스텔(보증금 4억~7억)** 매물을
하루 두 번 모아서 목록으로 보는 도구입니다.

- 수집: 내 PC에서 도는 Node 스크립트 (`collector/collect.js`) — 외부 라이브러리 0개
- 열람: 정적 웹앱 (`index.html`) — 수집된 JSON 파일만 읽습니다

---

## 0. 먼저 읽어 주세요 (중요)

**이 코드는 네이버 접속이 차단된 환경에서 작성되었습니다.**
개발 환경의 네트워크 정책이 `*.naver.com` 전체를 막고 있어(게이트웨이 403),
네이버가 실제로 어떤 응답을 주는지 **한 번도 확인하지 못했습니다.**

즉 이 수집기는 "조사한 스펙이 맞다면 동작한다" 상태입니다.
스펙의 근거는 제3자가 공개한 응답 캡처·요청 DTO·다수 구현체 교차 대조이며(자세한 내용은 `spec.md` 부록),
네이버 공식 문서가 아닙니다.

그래서 **첫 단계는 수집이 아니라 검증입니다.** 아래 1번을 먼저 실행해 주세요.

## 1. 첫 실행 — 스펙 검증 (`--verify`)

저장소 루트에서:

```bash
node apps/yeouido-jeonse/collector/collect.js --verify
```

- 네이버에 **총 8회 이하**만 요청합니다. 실패하면 파라미터를 바꿔가며 재시도하지 않고 즉시 멈춥니다.
- 검사 항목은 8개(V1~V8)이며 각각 `PASS` / `FAIL` / `SKIP`으로 표시됩니다.
- 결과는 `run-logs/verification.json`에도 저장됩니다.

### 결과 읽는 법

| 항목 | 무엇을 보는가 | FAIL이면 |
|---|---|---|
| **V7** | `m.land.naver.com/robots.txt`가 매물 목록 경로를 금지하는지 | **여기서 멈춥니다.** 수집을 진행하지 말고 알려 주세요 |
| **V3** | 지역 목록 API가 토큰 없이 되는지 + 여의도동 법정동코드 | 토큰을 요구하면 `config.json`의 `regions.manual` 사용 (4-3 참고) |
| **V1** | 매물 목록 API가 200을 주는지 ← **가장 중요** | 모바일 API 차단입니다. 수집 불가 — 반드시 보고해 주세요 |
| **V4** | 페이지당 건수와 `more` 플래그 동작 | 페이지 순회 조건을 고쳐야 합니다 |
| **V2** | 보증금 필터(`wprcMin`/`wprcMax`)가 실제로 동작하는지 | 자체 필터로 결과는 안전하지만 요청량이 늘어납니다 |
| **V5** | 응답이 대상 동으로 제한되는지 | 결과는 2차 자체 필터로 방어됩니다. bbox를 줄이면 좋습니다 |
| **V8** | 지도 축척/범위가 대상 동을 덮는지 | 범위를 넓혀야 합니다 |
| **V6** | 429(요청 제한) 임계 | **의도적으로 검사하지 않습니다** — 임계를 찾으려면 일부러 차단을 유발해야 하므로 |

### FAIL이 나오면 알려 주실 것

1. 콘솔 출력 전체 (특히 `↳` 로 시작하는 detail 줄)
2. `run-logs/verification.json` 파일
3. 첫 매물 1건의 필드 출력 (`prc`, `hanPrc`, `spc2`, `cortarNo` 값이 특히 중요합니다)

이 세 가지가 있으면 스펙을 고칠 수 있습니다.
**V1이 FAIL이면 그 자리에서 멈추고 알려 주세요.** 우회를 시도하지 않는 것이 이 도구의 원칙입니다
(브라우저 자동화나 IP 우회는 넣지 않았습니다).

## 2. 평소 수집

```bash
node apps/yeouido-jeonse/collector/collect.js
```

- 결과: `data/listings.json` (웹앱이 읽는 파일), `data/history.json` (매물별 이력)
- 실행 요약: `run-logs/last-run.json` — 실패가 있으면 종료 코드가 1이라 cron 로그에서 눈에 띕니다
- 소요 시간: 지역 수에 따라 보통 2~6분 (요청 간 2초 지연이 들어갑니다)

### 안전장치 (일부러 넣은 제약)

- 요청은 **순차 1건씩**, 사이에 2초(+무작위 지터) 지연
- 1회 실행 최대 150요청 / 하루 2회 = **최대 300요청**. 코드에 하드 상한(300)이 박혀 있습니다
- **429·403을 받으면 재시도하지 않고 즉시 중단**합니다. 밀어붙이면 차단이 길어집니다
- 대상 법정동 수 상한 40개 → 전국 대량 수집이 구조적으로 불가능합니다
- 병렬 요청·프록시 로테이션·IP 우회 기능은 **없습니다**

### 무엇이 잘못될 때 무엇이 일어나는가

| 상황 | 동작 |
|---|---|
| 어떤 지역 수집 실패 | 그 지역 매물을 **"사라짐"으로 판정하지 않습니다**(차단을 매물 소멸로 오독하지 않기). 화면에 경고 배너 |
| 매물 0건 | 오류가 아닙니다. 기존 `listings.json`을 **덮어쓰지 않고** 종료 |
| 응답 필드가 많이 비어 있음(30% 초과) | API 스키마 변경 의심 → 기존 데이터를 지키며 **실패로 종료** |
| `prc`와 `hanPrc` 금액이 안 맞음 | 금액 단위 전제가 틀렸을 수 있으므로 경고. 30% 초과면 실패 처리 |
| 저장 중 중단 | 임시 파일에 쓰고 이름을 바꾸므로 기존 파일이 깨지지 않습니다 |

### 요청만 미리 보기 (네트워크 접촉 없음)

```bash
node apps/yeouido-jeonse/collector/collect.js --dry-run
```

어떤 URL을 몇 번 보낼지, 예상 소요 시간까지 출력하며 **네트워크는 전혀 사용하지 않습니다.**

## 3. 설정 바꾸기 — `collector/config.json`

이 파일 하나만 편집하면 됩니다. (JSON은 주석을 못 쓰므로 `_comment` 키로 설명을 달아 두었습니다.)

### 3-1. 지역

```json
"include": [
  { "gu": "영등포구", "dong": "여의도동" },
  { "gu": "동작구",   "dong": "노량진동" }
]
```

- **동 이름만 적으면 됩니다.** 스크립트가 법정동코드를 찾고, `당산동1가`~`6가`처럼 쪼개진 하위 법정동까지 자동으로 펼칩니다.
- 기본 7곳: 여의도동, 당산동, 문래동, 영등포동, 양평동, 신길동, 노량진동
- **끄고 켜기**: `available_but_off`에 마포구 도화동·공덕동, 동작구 흑석동이 들어 있습니다.
  줄 하나를 `available_but_off`에서 `include`로 옮기면 켜집니다(반대로 옮기면 꺼집니다).
- 지역을 늘리면 요청 수가 비례해 늘어납니다. `maxRegionCodes`(기본 25, 하드 상한 40)에서 잘립니다.
- **알아 두실 것**: 기본 7곳은 하위 법정동까지 펼치면 **약 30개 코드**가 됩니다
  (영등포동은 `영등포동`+`1가~8가`로 9개, 당산동·문래동·양평동은 각 6개).
  기본 상한 25를 넘으므로 일부 `~가`가 빠지고, 어떤 코드가 빠졌는지 실행 로그에 경고로 나옵니다.
  상한을 넘을 때는 **설정한 동마다 돌아가며** 뽑으므로 신길동·노량진동처럼 코드가 1개인 지역이 통째로 빠지지는 않습니다.
  30개를 모두 수집하려면 `politeness.maxRegionCodes`를 `30`(또는 최대 `40`)으로 올리세요.
  이때 1회 실행 요청 수가 최대 150회(=30×5페이지)로 늘어나 `maxRequestsPerRun`(기본 150)에 근접합니다.

### 3-2. 금액·매물종류

```json
"tradeType": ["B1"],                    // B1 전세 (A1 매매 / B2 월세 / B3 단기임대)
"realEstateType": ["APT", "OPST"],      // 아파트 + 오피스텔
"depositMin": 40000,                    // 단위: 만원 → 4억
"depositMax": 70000,                    // 7억
"officetelMinExclusiveM2": 30           // 주거용 오피스텔 판별 기준(전용 30㎡ 이상)
```

**금액 단위는 만원입니다.** 7억은 `70000`이며 `700000000`이 아닙니다.
(실수하기 쉬운 곳이라, 값이 이상하면 스크립트가 실행 전에 막고 알려 줍니다.)

원룸형·업무용 오피스텔을 걸러내는 기준이 `officetelMinExclusiveM2`입니다. 25로 낮추거나 40으로 올릴 수 있습니다.

### 3-3. 지역 목록 API가 토큰을 요구할 때 (V3 FAIL 대응)

브라우저에서 네이버 부동산으로 여의도동을 열면 주소창이나 개발자도구 요청에 `cortarNo=...` 10자리 숫자가 보입니다.
그 값을 `config.json`에 넣으면 지역 목록 API 없이 수집할 수 있습니다.

```json
"manual": [
  { "cortarNo": "1156011000", "name": "여의도동", "gu": "영등포구",
    "centerLat": 37.5225, "centerLon": 126.9245 }
]
```

법정동코드는 공개된 행정 코드라 비밀이 아닙니다. 커밋해도 무해합니다.

### 3-4. 환경변수로 잠깐 바꾸기

```bash
YJ_DEPOSIT_MIN=45000 YJ_DEPOSIT_MAX=65000 node apps/yeouido-jeonse/collector/collect.js
```

`YJ_DEPOSIT_MIN`, `YJ_DEPOSIT_MAX`, `YJ_MAX_PAGES`, `YJ_DELAY_MS`를 지원합니다.

## 4. 하루 2회 자동 실행 등록

기본 주기는 **08:00 / 20:00 (한국 시간)** 입니다.
PC가 꺼져 있으면 그 회차는 건너뛰고, 다음 실행이 따라잡습니다(전세 매물은 분 단위로 바뀌지 않습니다).

### macOS / Linux — cron

```bash
crontab -e
```

편집기가 열리면 아래 한 줄을 넣습니다. `<저장소경로>`는 이 저장소의 절대 경로로 바꿔 주세요
(예: `/Users/junho/my-blog`). `node` 경로는 `which node`로 확인합니다.

```
0 8,20 * * * cd <저장소경로> && /usr/bin/node apps/yeouido-jeonse/collector/collect.js >> apps/yeouido-jeonse/run-logs/cron.log 2>&1
```

- 잘 등록됐는지: `crontab -l`
- 실행 결과는 `run-logs/cron.log`와 `run-logs/last-run.json`에 쌓입니다
- macOS는 처음 실행 시 "터미널이 파일에 접근하려 합니다" 권한 창이 뜰 수 있습니다 — 허용해 주세요

### Windows — 작업 스케줄러

1. 시작 메뉴에서 **작업 스케줄러** 실행 → 오른쪽 **작업 만들기**
2. **일반** 탭: 이름 `여의도 전세 수집`
3. **트리거** 탭 → 새로 만들기 → 매일, 시작 `08:00` → 확인.
   다시 새로 만들기 → 매일, 시작 `20:00` → 확인 (트리거 2개)
4. **동작** 탭 → 새로 만들기 → 작업: `프로그램 시작`
   - 프로그램/스크립트: `node.exe`의 전체 경로 (PowerShell에서 `where.exe node`로 확인. 보통 `C:\Program Files\nodejs\node.exe`)
   - 인수 추가: `apps\yeouido-jeonse\collector\collect.js`
   - 시작 위치: 저장소 폴더 경로 (예: `C:\Users\junho\my-blog`) ← **비워두면 실패합니다**
5. **조건** 탭: "컴퓨터의 AC 전원이 켜져 있을 때만 실행"을 필요에 따라 해제

등록 후 목록에서 작업을 선택해 **실행**을 눌러 한 번 수동 확인하는 것을 권합니다.

## 5. 화면 보기

웹앱은 정적 파일이라 서버로 띄워야 합니다(브라우저에서 파일을 직접 열면 `fetch`가 차단됩니다).

```bash
node build.js
node tools/serve.js
```

→ 브라우저에서 **http://localhost:8642/apps/yeouido-jeonse/**

`build.js`가 `apps/`를 `dist/`로 복사하므로, **수집한 뒤에는 `build.js`를 다시 실행해야** 새 데이터가 화면에 반영됩니다.

화면에서 할 수 있는 것:

- 필터: 지역 / 종류(아파트·오피스텔) / 보증금 범위(슬라이더 + `4~5억` 같은 프리셋) / 전용면적 최소 / 신규만 / 가격내림만 / 사라진 매물 포함
- 정렬: 확인일 최신순(기본) · 보증금 낮은순 · 높은순 · 전용면적 넓은순 · 최초 관측 최신순
- 배지: 🆕 신규 · 💰 가격 내림 · 📈 가격 오름 · 🚫 사라짐 · ⚠️ 확인 보류
- 필터 상태가 주소(URL)에 저장되므로 새로고침하거나 링크를 보내도 유지됩니다
- 각 카드의 **네이버에서 보기 ↗** 로 원본 매물 페이지로 이동합니다

> 화면의 필터는 **이미 수집된 데이터를 좁혀 보는** 기능입니다.
> 무엇을 수집할지는 `collector/config.json`에서만 바뀝니다.

## 6. 실제 데이터는 커밋되지 않습니다

`spec.md`의 결정 D1에 따라:

- `data/listings.json`, `data/history.json`, `data/regions.cache.json`, `run-logs/*`는 **gitignore** 되어 있습니다
  (앱 폴더 안에 중첩 `.gitignore`를 두었습니다 — 저장소 루트 설정은 건드리지 않았습니다)
- 수집한 매물 정보를 공개 웹에 재배포하지 않기 위한 조치입니다
- 그래서 **공개된 블로그에서는 `data/sample.json`(예시 데이터)이 표시**되고, 화면 상단에 "예시 데이터입니다" 배너가 항상 뜹니다
- 예시 데이터의 단지명은 모두 `예시아파트 A`, `샘플오피스텔 C`처럼 명백한 가짜이며 원본 링크도 없습니다
- 실제 매물은 **내 PC에서만** 보입니다

```
apps/yeouido-jeonse/
├── index.html            화면
├── style.css             스타일 (모바일 1열, 다크모드)

├── collector/
```

## 8. 자주 막히는 곳

| 증상 | 확인할 것 |
|---|---|
| 화면에 "file:// 로 열면…" 안내가 뜬다 | `node build.js` → `node tools/serve.js` 로 접속하세요 |
| 화면에 "표시할 데이터가 없습니다" | 아직 수집 전이거나 `build.js`를 다시 돌리지 않았습니다 |
| 화면 데이터가 낡았다 | 수집 후 `node build.js`를 다시 실행해야 `dist/`에 복사됩니다 |
| `[실패] 네트워크 연결 실패` | 사내망·VPN·프록시가 naver.com을 막고 있을 수 있습니다. 가정용 네트워크에서 다시 시도 |
| `[실패] HTTP 429/403` | 차단입니다. **재시도하지 마세요.** 다음 주기(또는 하루)를 기다리세요 |
| 수집은 되는데 매물이 0건 | 보증금 4~7억 조건이 좁을 수 있습니다. `config.json`에서 범위를 넓혀 보세요 |
| 원인을 더 보고 싶다 | `YJ_DEBUG=1`을 붙여 실행하면 스택 트레이스까지 출력됩니다 |

## 9. 이 도구가 지키는 선

네이버 이용약관은 자동화된 수단의 데이터 수집을 제한하며, 매물 정보의 무단 재배포는 정보제공업체와 네이버 양측의 권리를 침해할 수 있습니다.
그래서 이 도구는 **"내가 브라우저로 여의도 매물을 하루 두 번 훑어보는 것"** 수준을 넘지 않도록 설계했습니다.

- 목적: 본인 주거(전세) 탐색. 상업적 이용·재판매 없음
- 분량: 하루 최대 300요청, 관심 지역 7~10개 동
- 속도: 순차 요청 + 최소 1초 지연 (기본 2초)
- 차단 존중: 429/403이면 재시도 없이 물러남
- 재배포: 수집 데이터는 공개 저장소에 올리지 않음(D1)
- 표시: 항상 원본 링크를 함께 보여 트래픽을 네이버로 되돌림

`--verify`의 V7에서 robots.txt가 목록 경로를 금지하는 것으로 확인되면, 그 자리에서 중단하고 보고하도록 만들어 두었습니다.

# Build 서브에이전트 지침 — 여의도 전세 매물 수집기

## 역할

너는 Build 단계 서브에이전트다. `spec.md`에 승인된 계획을 **구현**한다.
검증(Review)은 별도 서브에이전트가 맡으므로 너는 `review.md`를 쓰지 않는다.

## 먼저 읽을 것 (순서대로)

1. `/home/user/my-blog/apps/yeouido-jeonse/spec.md` ← **구현의 근거. 전체를 읽어라.**
2. `/home/user/my-blog/CLAUDE.md` ← 프로젝트 규칙
3. `/home/user/my-blog/apps/2048/` 와 `/home/user/my-blog/apps/pixel-art/` ← 기존 앱의 코드 스타일·구조를 따를 것
4. `/home/user/my-blog/build.js` 의 앱 복사 부분(498~505행) 과 `/home/user/my-blog/tools/serve.js`

## ⚠️ 이 환경의 결정적 제약 — 반드시 먼저 이해할 것

**이 실행 환경은 네트워크 정책으로 `*.naver.com` 전체를 차단한다.** 확인된 사실이다:

```
CONNECT m.land.naver.com:443   → gateway 403 (policy denial)
CONNECT new.land.naver.com:443 → gateway 403 (policy denial)
```

따라서:

- **네이버에 실제 요청을 보내려고 시도하지 마라.** 우회하려 하지 마라(프록시 탐색, 다른 호스트명, DNS 우회 등 전부 금지).
- `spec.md` 10장의 **0단계(라이브 검증)를 네가 수행할 수 없다.** 대신 **아래 "V모드 요구사항"대로 사용자가 자기 PC에서 1회 실행할 검증 명령을 구현**해서 넘긴다.
- 따라서 **너의 코드는 "스펙이 맞다면 동작한다" 상태로 끝난다.** 이 사실을 숨기지 말고, 코드와 README 양쪽에 명확히 남겨라.
- **스펙과 현실이 다를 때 조용히 잘못된 값을 내놓지 않는 것**이 이 구현의 최우선 품질 기준이다. 응답 필드가 없거나 형태가 다르면 추측해서 채우지 말고, 명확한 에러/경고로 드러내라.

## 수정 허용 범위 (엄격)

**`apps/yeouido-jeonse/` 안에서만 작업한다.** 이 폴더 밖의 파일은 **읽기만** 하고 절대 만들거나 수정하지 않는다.
특히 다음을 건드리지 마라: 루트 `index.html`·`build.js`·루트 `.gitignore`·`src/`·`posts/`·`tools/`·`.github/`.

- 메인 페이지 카드 임베드는 **Embed 단계**의 일이다. 네가 하지 않는다.
- `spec.md`와 `PLAN-INSTRUCTIONS.md`를 수정하지 마라.
- **git 커밋·푸시를 하지 마라.** 커밋은 상위 세션이 처리한다.

## 기술 제약

- **의존성 0.** Node 18+ 내장만 (`node:fs`, `node:path`, `node:process`, 전역 `fetch`). npm 설치 금지
- 웹앱은 순수 HTML/CSS/JS. 외부 라이브러리·CDN 금지 (지도 SDK 포함)
- 모바일 필수 — 320px 폭에서 깨지지 않아야 한다
- 기존 앱과 코드 스타일 일치 (`'use strict'`, 주석 밀도, 한국어 주석, 네이밍)

## V모드 요구사항 — `node collector/collect.js --verify`

라이브 검증을 사용자가 대신 수행할 수 있게 만드는 명령이다. **이것이 이번 Build의 가장 중요한 산출물이다.**

- `spec.md` 2.6의 **V1~V8**을 순서대로 점검하고, 각 항목을 `PASS` / `FAIL` / `SKIP`으로 사람이 읽기 쉽게 콘솔에 출력한다
- **총 요청 8회를 넘지 않는다.** 실패하면 파라미터를 바꿔가며 재시도하지 말고 즉시 멈추고, 무엇을 확인해야 하는지 안내한다
- 순서: robots.txt(V7) → `regions/list` 및 토큰 필요 여부(V3) → 여의도동 cortarNo 확인(V3) → `articleList` 1회(V1, V4) → `wprc` 필터 유무 비교(V2)
- **V7에서 목록 경로가 robots.txt로 금지되어 있으면 나머지를 실행하지 않고 중단**하며 그 사실을 크게 출력한다
- V1이 실패하면 "모바일 API 차단 — D6에 따라 중단. 상위 세션에 보고 필요"를 출력하고 종료 코드 1
- 결과를 `run-logs/verification.json`에 기록한다
- 응답 원문 일부를 사용자가 눈으로 확인할 수 있게 축약 출력한다(첫 매물 1건의 주요 필드)

`--dry-run`은 요청 URL 목록만 출력하고 네트워크를 전혀 타지 않아야 한다. **이 환경에서 너 스스로 반드시 실행해 검증하라.**

## 방어적 구현 요구사항

- **금액 단위**: `prc`가 만원 단위라는 전제가 틀리면 4억이 4조로 표시된다. 정규화 시 `prc`(숫자)와 `hanPrc`(한글 표기)를 **교차 검증**해 불일치하면 경고를 남긴다
- **`rletTpCd` 코드 체계가 요청/응답에서 다름** (요청 `APT`/`OPST` ↔ 응답 `A01`/`A02`) — 응답은 `rletTpNm`(한글명)을 신뢰하고 코드는 매핑 테이블로 처리
- **응답 `cortarNo`로 2차 자체 필터링** — bbox가 인접 동을 물어와도 결과가 오염되지 않게
- **필드 누락 허용**, 단 누락률 30% 초과 시 스키마 변경으로 판단해 **기존 `listings.json`을 보존한 채 실패 처리**
- **부분 실패 시 삭제 판정 보류** — 실패한 지역의 매물을 "사라졌다"로 오독하지 않는다 (spec 8.3)
- **매물 0건은 에러가 아니다** — 정상 처리하고 기존 데이터를 지우지 않는다
- **원자적 저장** — 임시 파일에 쓰고 rename. 중간에 죽어도 기존 파일이 깨지지 않게
- 상한을 코드에 고정: 1일 300요청, 대상 코드 40개, 지역당 페이지 상한, 요청 간 최소 1초 지연, **429/403은 재시도 없이 즉시 중단**
- 병렬 요청·프록시 로테이션·IP 우회 기능을 **넣지 않는다**

## `sample.json` 규칙 (중요)

공개 사이트에 배포되는 파일이므로 다음을 지켜라.

- **실재하는 매물처럼 보이는 조작 데이터를 만들지 마라.** 단지명은 `예시아파트 A`, `샘플오피스텔 B`처럼 **명백히 예시임을 알 수 있는 이름**을 쓰고, 중개사명·매물번호도 실재를 암시하지 않는 자리표시자로 둔다
- 최상위에 `"is_sample": true`를 넣고, **웹앱은 이 값이 true이면 화면 상단에 "예시 데이터입니다" 배너를 항상 표시**한다
- 6~10건 정도. 신규/가격변동/사라진 매물 배지와 필터·정렬을 모두 시연할 수 있게 구성

## 웹앱 요구사항

- `spec.md` 7장을 따른다. 목록·필터(지역/평형/보증금/매물종류)·정렬·배지(신규/가격변동)·원본 링크(`m.land.naver.com/article/info/{atclNo}`)
- **데이터 로딩 폴백**: `data/listings.json`을 먼저 시도 → 없으면 `data/sample.json` → 둘 다 없으면 안내 메시지. 어느 것을 쓰는지 화면에 명시
- `file://`로 열면 fetch가 실패한다 → 그 경우 "`node tools/serve.js`로 실행하세요"라는 **구체적 안내**를 화면에 표시
- 푸터: "네이버 부동산 공개 매물 정보를 개인 열람 목적으로 수집. 정확한 정보는 원본을 확인하세요."
- 0건·에러·오프라인 상태를 각각 다르게 표시

## README 요구사항 (`apps/yeouido-jeonse/README.md`)

사용자(비개발자 관점)가 자기 PC에서 바로 따라할 수 있게 한국어로 작성한다.

1. **첫 단계로 `node collector/collect.js --verify`를 실행하라**는 것과, 그 이유(이 코드는 네이버 접속이 차단된 환경에서 작성되어 **라이브 검증이 되지 않았다**)를 정직하게 명시
2. V모드 결과를 어떻게 읽는지, FAIL이 나오면 무엇을 알려줘야 하는지
3. 평소 수집 실행법, `config.json`으로 지역·금액·매물종류 바꾸는 법
4. 주기 실행 등록법 — macOS/Linux `cron`, Windows 작업 스케줄러 각각 1일 2회(08시·20시) 예시
5. 화면 보는 법 (`node tools/serve.js` → 브라우저 주소)
6. D1에 따라 **실데이터는 커밋되지 않는다**는 점과, 그래서 공개 사이트에는 예시 데이터가 보인다는 점

## 자체 검증 (네가 끝내기 전에 반드시 실행)

1. `node --check`로 모든 JS 파일 문법 확인
2. `node collector/collect.js --dry-run` 실행 → 요청 URL 목록이 나오고 네트워크를 타지 않는지 확인
3. `node collector/collect.js --verify` 실행 → **차단 환경이므로 실패가 정상.** 실패를 **깔끔한 에러 메시지로 안내하는지**(스택 트레이스를 그대로 토하지 않는지) 확인
4. `diff.js`를 단독으로 호출해 신규/삭제/가격변동 3케이스가 정확히 판정되는지 확인 (임시 검증 스크립트는 스크래치패드에 두고, 저장소에 남기지 마라)
5. `node build.js`를 실행해 빌드가 깨지지 않고 `dist/apps/yeouido-jeonse/`에 파일이 복사되는지 확인 → **확인 후 `dist/`는 gitignore되어 있으니 그대로 두면 된다**
6. `node tools/serve.js`로 띄워 브라우저 없이라도 HTML/CSS/JS 정합성을 최대한 점검. 320px 반응형은 CSS를 직접 읽어 검토

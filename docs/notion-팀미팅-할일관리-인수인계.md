## 3. 정기 운영 워크플로우 ★핵심

사용자가 회의 후 **"이번 회의록 할일 정리해줘"** (회의록 링크 첨부) 라고 요청하면 아래를 수행합니다.

### 1단계 — 회의록 읽기
`notion-fetch`로 해당 회의록 페이지를 가져옵니다.
할일 소스는 세 군데이며 **전부** 확인해야 합니다.

1. `### 회의안건(Fr. Slack)` 본문
2. `### AI Note 회의록` 안의 `### 액션 아이템` 체크리스트
3. AI Note 요약 본문 — 액션 아이템 목록에 빠졌지만 실제 후속 조치가 필요한 내용이 자주 섞여 있음

> AI Note는 STT 기반이라 고유명사가 자주 깨집니다.
> (실제 사례: "민나우체 발송" → 미납 업체 리마인더, "JW 코멘트" → JW통신/코메타,
> "버스 리마인드" → 위멤버스 리마인드, "솔루션 테스트" → 솔루션택스)
> 회의안건 원문과 대조해 복원하되, **확신이 없으면 임의로 확정하지 말고 비고에 원문을 병기**합니다.

### 2단계 — 팀 할일 DB에 등록
`notion-create-pages`로 `data_source_id: 295b4212-870e-4c2c-9e05-aab5bb3c3e28`에 일괄 생성합니다.

작성 규칙:
- **할일** — "무엇을 어떻게" 가 드러나게. `발송`, `확인`, `확정`처럼 완료 판정이 가능한 동사로 끝냄
- **상태** — 신규는 항상 `미착수`
- **기한** — 회의록이 시간 구분을 쓰면 그대로 매핑 (오늘=회의 다음 영업일, 이번 주=그 주 금요일, 이번 달=월 중순). 명시가 없으면 회의 주 금요일
- **관련 회의** — 회의록 페이지 URL을 배열로. 필수
- **관련 거래처** — 거래처명 쉼표 구분
- **비고** — 출처(예: `260727 회의 '이번 주' 항목`)와 맥락. 의사결정 대기·회신 대기 같은 상태도 여기 기록
- 팀 차원의 판단이 필요한 항목은 제목 앞에 **`[의사결정]`** 태그를 붙임

중복 방지: 등록 전 `notion-query-data-sources`로 미완료 항목을 조회해 같은 건이 이미 있는지 확인합니다.
이전 회의에서 넘어온 항목이면 새로 만들지 말고 기존 항목의 `관련 회의`에 이번 회의록을 추가하세요.

### 3단계 — 회의록 페이지에 할일 목록 추가
`notion-update-page` (`insert_content`, `position: {"type":"end"}`)로 회의록 하단에 섹션을 추가합니다.

형식 (260727 회의록이 실제 샘플):

```markdown
### 이 회의에서 나온 할일 & F/u

> 아래 항목은 [팀 할일 DB](https://app.notion.com/p/4b80ea2f01ca4dae86ddbcb4dddc272c)에서 관리됩니다. 진행 상태·담당자는 DB에서 확인·변경하세요.

**기한 ~7/30**
- [할일 제목](생성된 페이지 URL)
- [할일 제목](생성된 페이지 URL)

**기한 ~7/31**
- [할일 제목](생성된 페이지 URL)
```

`notion-create-pages` 응답에 각 항목의 URL이 들어 있으니 그대로 링크에 씁니다.

### 4단계 — 이전 할일 정리
사용자가 완료 항목을 알려주면 해당 페이지의 `상태`를 `완료`로 변경합니다.
기한이 지났는데 미완료인 항목은 정리하면서 사용자에게 짚어줍니다.

## 4. MCP 도구 사용 시 실전 주의사항

이 구조를 만들면서 실제로 부딪힌 것들입니다. 모르면 시간을 크게 낭비합니다.

### ⚠️ 관계형(Relation) 필터는 View DSL에서 동작하지 않음
`notion-create-view` / `notion-update-view`의 `configure`에 `FILTER "관련 회의" ...`를 넣으면
**오류 없이 조용히 무시**됩니다 (응답의 `advancedFilter.filters`가 빈 배열로 돌아옴).
`CONTAINS`로 URL·제목·날짜 문자열 매칭을 시도해도 마찬가지입니다.

→ 그래서 "회의별 할일 뷰"를 자동 생성하는 방식을 **포기하고**, 3단계처럼 회의록에 링크 목록을 직접 쓰는 방식으로 확정했습니다.
사람이 Notion UI에서 자기참조 필터를 걸면 가능하지만, 사용자가 매번 수동 설정을 원하지 않아 현재 방식을 택했습니다.
**이 결정을 되돌리지 마세요.**

### 속성 값 형식
- **날짜** — `기한`이 아니라 `date:기한:start`로 넘김 (`date:기한:end`, `date:기한:is_datetime`도 별도 키)
- **관계** — 페이지 URL 문자열의 JSON 배열: `["https://app.notion.com/p/3aa..."]`
- **PEOPLE** — user ID 배열. 이름 문자열은 안 됨. `notion-search`에 `query_type: "user"`로 ID를 먼저 조회
- **선택(Select)** — 옵션명이 정확히 일치해야 함

### 콘텐츠 수정
- `update_content`로 인라인 DB가 포함된 영역을 지우면 400 에러가 납니다. 의도한 삭제라면 `allow_deleting_content: true`를 함께 넘기세요.
- 부분 수정은 `update_content`(검색·치환) 또는 `insert_content`를 쓰고, `replace_content`는 피하세요.

### 그 밖에
- 페이지 삭제(휴지통 이동)는 MCP로 불가능합니다. 사용자에게 Notion UI에서 직접 삭제해달라고 요청하세요.
- 회의록 DB의 레거시 텍스트 속성 `추후할일`은 과거 기록 보존용으로 남아 있습니다. Notion AI가 자동으로 채우기도 하지만, **정식 관리 대상이 아닙니다.** 할일의 정본은 팀 할일 DB입니다.

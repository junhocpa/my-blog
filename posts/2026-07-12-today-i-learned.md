클로드 코드와 함께 이 블로그를 직접 만들면서, 웹페이지를 이루는 세 가지 언어가 각자 어떤 역할을 맡는지 몸으로 배웠다. 프레임워크 없이 만들었기 때문에 세 언어의 경계가 오히려 더 선명하게 보였다.

## HTML — 구조와 의미

HTML은 페이지의 **뼈대**다. 글 제목, 본문, 날짜, 목록 같은 콘텐츠를 담고, 각 내용이 무엇인지 의미를 부여한다.

- 이 블로그의 글 하나는 `<article>`, 날짜는 `<time>`, 이전/다음 글 링크는 `<nav>`로 표시한다.
- 이렇게 의미에 맞는 태그(시맨틱 태그)를 쓰면 브라우저, 검색 엔진, 스크린 리더가 페이지 구조를 이해할 수 있다.
- HTML만 있어도 페이지는 완전히 읽을 수 있다. 꾸미기와 동작은 그 위에 얹는 것이다.

## CSS — 모양과 배치

CSS는 HTML이라는 뼈대에 입히는 **옷**이다. 색, 글꼴, 간격, 배치를 담당한다.

- 본문 너비를 700px로 제한하고 줄 간격을 1.7로 잡은 것만으로 글 읽기가 훨씬 편해졌다.
- 색상을 전부 CSS 변수로 정의해 두니, 다크 모드는 변수 값만 통째로 바꾸는 것으로 해결됐다.
- 미디어 쿼리 덕분에 같은 HTML이 휴대폰에서도 데스크톱에서도 알맞게 보인다.

## JavaScript — 동작과 상호작용

JavaScript는 페이지에 **움직임**을 더한다. 사용자의 행동에 반응하는 부분은 전부 JS의 몫이다.

- 테마 토글 버튼을 누르면 JS가 `data-theme` 속성을 바꾸고, 선택을 `localStorage`에 저장해 다음 방문에도 기억한다.
- 태그를 클릭하면 JS가 목록에서 해당 태그의 글만 남기고 숨긴다.
- 중요한 배움: JS가 꺼져 있어도 글은 전부 읽을 수 있게 만들었다. JS는 편의를 더할 뿐, 콘텐츠를 인질로 잡으면 안 된다.

## 세 언어의 관계

| 언어 | 역할 | 이 블로그에서의 예 |
| --- | --- | --- |
| HTML | 구조와 의미 | 글, 목록, 날짜, 내비게이션 |
| CSS | 모양과 배치 | 타이포그래피, 다크 모드, 반응형 |
| JavaScript | 동작과 상호작용 | 테마 토글, 태그 필터 |

> 구조(HTML) 위에 스타일(CSS)을 입히고, 그 위에 동작(JS)을 얹는다. 아래층이 튼튼하면 위층이 없어도 무너지지 않는다.
